
## 1. 项目结构

过程宏需要放在独立的 `proc-macro` 库中，另一个项目负责使用它。 [doc.rust-lang](https://doc.rust-lang.org/book/ch20-05-macros.html)

```text
macro-demo/
├─ Cargo.toml
├─ hello_derive/
│  ├─ Cargo.toml
│  └─ src/
│     └─ lib.rs
└─ app/
   ├─ Cargo.toml
   └─ src/
      └─ main.rs
```

在 PowerShell 中创建：

```powershell
mkdir macro-demo
cd macro-demo

cargo new hello_derive --lib
cargo new app
```

## 2. 根目录 Cargo.toml

新建 `macro-demo/Cargo.toml`：

```toml
[workspace]
members = ["hello_derive", "app"]
resolver = "2"
```

## 3. 宏库配置

将 `hello_derive/Cargo.toml` 改成：

```toml
[package]
name = "hello_derive"
version = "0.1.0"
edition = "2021"

[lib]
proc-macro = true

[dependencies]
syn = "2"
quote = "1"
```

`proc_macro` 由 Rust 提供，不需要在 `[dependencies]` 中添加；`syn` 和 `quote` 是第三方依赖。 [docs](https://docs.rs/syn)

## 4. 过程宏实现

将 `hello_derive/src/lib.rs` 改成：

```rust
// 编译器提供的过程宏输入、输出类型。
use proc_macro::TokenStream;

// 用 Rust 代码模板生成 token。
use quote::quote;

// 将输入 token 解析为语法树。
use syn::{parse_macro_input, DeriveInput};

// 注册名为 Hello 的 derive 宏。
// 使用方写 #[derive(Hello)] 时，编译器调用这个函数。
#[proc_macro_derive(Hello)]
pub fn derive_hello(input: TokenStream) -> TokenStream {
    // 第一步：syn 解析输入。
    // 例如 struct Robot; 会被解析成 DeriveInput。
    let syntax_tree = parse_macro_input!(input as DeriveInput);

    // 第二步：取得类型名。
    // 例如 Robot。
    let type_name = &syntax_tree.ident;

    // 取得泛型和 where 约束，生成 impl 时保留它们。
    let (impl_generics, type_generics, where_clause) =
        syntax_tree.generics.split_for_impl();

    // 第三步：quote 根据模板生成输出 token。
    //
    // #type_name 不是注释。
    // 它表示把上面取得的类型名插入模板。
    let generated = quote! {
        impl #impl_generics #type_name #type_generics #where_clause {
            pub fn hello(&self) {
                println!("Hello，我是 {}", stringify!(#type_name));
            }
        }
    };

    // 第四步：转换为编译器要求的 proc_macro::TokenStream。
    generated.into()
}
```

这遵循 `syn` 官方示例的基本流程：接收 `TokenStream` → 解析 `DeriveInput` → 生成 token → 返回给编译器。`split_for_impl()` 用于正确拆分并保留泛型声明、类型参数和 `where` 子句。 [docs](https://docs.rs/syn)

这个教学宏生成的是类型自己的方法，没有生成某个 trait 的实现；derive 宏也可以生成这样的代码。

## 5. 使用方配置

将 `app/Cargo.toml` 改成：

```toml
[package]
name = "app"
version = "0.1.0"
edition = "2021"

[dependencies]
hello_derive = { path = "../hello_derive" }
```

将 `app/src/main.rs` 改成：

```rust
use hello_derive::Hello;

#[derive(Hello)]
struct Robot;

#[derive(Hello)]
struct Sensor<T> {
    value: T,
}

fn main() {
    let robot = Robot;
    robot.hello();

    let sensor = Sensor { value: 123 };
    sensor.hello();

    println!("传感器数值：{}", sensor.value);
}
```

在工作区根目录运行：

```powershell
cargo run -p app
```

预期输出：

```text
Hello，我是 Robot
Hello，我是 Sensor
传感器数值：123
```

## 6. 编译时究竟发生什么

对这个输入：

```rust
#[derive(Hello)]
struct Robot;
```

处理过程是：

```text
编译器遇到 #[derive(Hello)]
    ↓
proc_macro：
    把 struct Robot; 作为 TokenStream 交给宏
    ↓
syn：
    解析成语法树，取得类型名 Robot
    ↓
quote：
    将 Robot 插入代码模板，生成 token
    ↓
proc_macro：
    将生成的 TokenStream 返回给编译器
    ↓
编译器继续编译原类型和新增代码
```

概念上的新增代码是：

```rust
impl Robot {
    pub fn hello(&self) {
        println!("Hello，我是 {}", stringify!(Robot));
    }
}
```

derive 宏不会在运行时生成方法，也不会删除原来的 `struct Robot`；它在编译时添加代码。 [docs](https://docs.rs/syn)

因此：

```text
编译时：执行 derive_hello，生成 hello 方法
运行时：执行 robot.hello()，打印消息
```

最重要的对应关系：

| 工具 | 本例代码 | 职责 |
|---|---|---|
| `proc_macro` | `input: TokenStream`、返回 `TokenStream` | 与编译器交接代码 token |
| `syn` | `parse_macro_input!`、`syntax_tree.ident` | 解析并读取代码结构 |
| `quote` | `quote! { ... #type_name ... }` | 用模板构造输出代码 |

记忆：`proc_macro` 收发，`syn` 拆解，`quote` 组装。 [docs](https://docs.rs/syn)
